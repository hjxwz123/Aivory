## What's Changed

Aivory 2.4.5 adds user-managed MCP services to personal and shared workspace libraries, introduces finer workspace capability and member permission controls, and keeps model, tool, and resource availability aligned with those policies throughout the application. It also improves OpenAI Responses replay compatibility and shows the current conversation title in the browser tab.

### User MCP Services

- Adds personal and workspace-shared Streamable HTTP MCP services to the resource library alongside skills and prompts.
- Users with the required permission can create, edit, enable, disable, and delete MCP services with custom request headers.
- New MCP services perform initial tool discovery when possible and expose explicit connection-test and tool-resync actions.
- Shows connection state and discovered tool counts in the library, while preserving the last successful snapshot when a later discovery attempt fails.
- Adds an "Official tools" / "My tools" switch to the chat tool picker so user-managed MCP tools remain easy to identify and select.
- Keeps personal MCP services private to their owner; shared workspace services follow workspace membership, capability, and ownership rules.
- Clears stale explicit tool selections when switching workspace scope so tools from one workspace cannot carry into another.

### Workspace Capabilities

- Reorganizes workspace policy controls into core capabilities, resource-library families, and workspace content.
- Adds independent workspace switches for tool calling, drawing, MCP services, skills, prompts, knowledge bases, and file uploads.
- Treats tool calling as the workspace-wide gate for built-in, hosted, administrator MCP, and user MCP tools.
- Keeps direct drawing and image-model availability independent from ordinary tool calling.
- Applies workspace-wide capability switches to every member, including workspace administrators.
- Filters model pickers, image models, tool catalogs, command menus, projects, knowledge bases, uploads, and library views to match the active workspace policy.
- Adds a manager-specific model catalog for editing model allowlists without silently omitting models hidden by the manager's own account permissions.
- Prevents conversations from storing a model that is unavailable under the active workspace policy.

### Member Permissions

- Splits the former combined skill-and-prompt creation permission into independent prompt, skill, and MCP creation permissions.
- Adds separate permissions for using workspace prompts, skills, and MCP services.
- Groups member controls by resource use, resource creation, and workspace content for easier administration.
- Keeps creation and use independent: a member can be allowed to maintain a resource without automatically receiving permission to use it.
- Preserves compatible behavior for older clients and migrates legacy combined permissions without broadening an existing restriction.
- Detects realtime permission or policy changes while an editor has unsaved work, preserves the draft, blocks stale saves, and asks the administrator to reload.
- Cancels active member generations when a capability reduction removes authority needed by the running request.

### OpenAI Responses Compatibility

- Rebuilds stored assistant history as portable Responses API input messages instead of replaying status-dependent provider output objects.
- Repairs legacy persisted assistant output during replay and removes provider-specific message identifiers that are unsafe to reuse.
- Marks terminal function and hosted-tool call items as completed when replaying tool loops.
- Keeps compatible text history when changing models, provider channels, API formats, or tool replay modes.
- Fixes follow-up requests rejected by OpenAI-compatible Responses gateways because historical assistant content used an invalid `output_text` input shape.
- Preserves partial assistant text and valid tool continuation items across interrupted or compatibility-fallback responses.

### Chat Experience

- Shows the active conversation title in the browser tab as `<conversation> | Aivory`.
- Uses the localized untitled label when a conversation has no title.
- Restores the application title when leaving the conversation page.

### Security and Access Enforcement

- Enforces workspace resource and tool restrictions at API, catalog, orchestration, and runtime execution boundaries rather than relying on UI visibility.
- Restricts user-managed MCP connections at dial time to resist DNS rebinding and block loopback, link-local, cloud-metadata, unspecified, multicast, and reserved destinations.
- Allows private-LAN MCP endpoints by design while continuing to block access to the application host and metadata addresses.
- Limits MCP redirects to the same authority and rejects HTTPS-to-HTTP downgrades so custom credentials are not forwarded to another origin or exposed on a downgraded hop.
- Keeps MCP header values write-only in API responses and sanitizes discovery errors and remote tool metadata before storing or displaying them.
- Retires stale MCP discovery snapshots when endpoint credentials change or a service is re-enabled, and uses compare-and-swap updates to prevent concurrent discovery results from restoring obsolete state.
- Rechecks MCP ownership, workspace scope, membership, and capabilities at execution time and invalidates cached sessions after updates, deletion, or workspace teardown.

### Verification

- Adds backend coverage for personal and workspace MCP lifecycle operations, authorization, tool discovery, runtime routing, cache invalidation, and workspace policy enforcement.
- Adds network-safety coverage for DNS resolution, restricted destinations, redirects, protocol downgrades, and credential redaction.
- Adds migration and store coverage for granular workspace permissions, legacy compatibility, MCP persistence, and concurrent metadata or sync updates.
- Adds OpenAI Responses regression coverage for legacy history, model and channel switches, partial responses, and tool-loop replay.
- Adds frontend coverage for workspace capability resolution, permission state, model-cache isolation, tool segmentation, resource state, and browser document titles.

### Upgrade Notes

- No new mandatory environment variable is required.
- Database migrations run automatically, create the user MCP storage table, and add the new workspace capability and member permission columns.
- Existing combined resource permissions and legacy workspace tool or image switches are migrated conservatively so an upgrade does not broaden a prior restriction.
- Back up the instance before upgrading and allow one application instance to complete migration before scaling out.
- Version-pinned Docker deployments should set `IMAGE_TAG=2.4.5` after the application, sandbox runner, and sandbox sidecar workflows publish matching `linux/amd64` and `linux/arm64` images.
- User-managed MCP integrations must expose a Streamable HTTP endpoint. Localhost and link-local endpoints are intentionally rejected; private-LAN addresses remain supported.

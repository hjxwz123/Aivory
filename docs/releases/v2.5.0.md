# Aivory v2.5.0

This stable release combines the final behavior of **all seven 2.5.0 betas**. It also summarizes the changes between v2.4.0 and v2.4.9 for readers upgrading directly from v2.4.0.

## Files become part of the conversation

- The unified artifact panel opens streamed HTML, conversation attachments, sandbox outputs, generated files, and knowledge-base documents beside chat. Its desktop width can be resized by pointer or keyboard and persists; mobile uses a sheet. Generated-file cards have a direct preview action.
- Browser editing supports text, code, HTML with a live preview, DOCX, XLSX, and **text in existing PPTX slides**. Edited files can be downloaded or saved as new copies. PPTX editing does not add or redesign slide objects; the XLSX grid is limited to 2,000 rows and 100 columns and implements only a subset of formulas. Complex Office files may render differently from desktop Office applications.
- The final folder-upload flow sends a selected directory in one request to the current conversation sandbox. It preserves bytes and relative paths under `/workspace/folders/<folder>/`, shows the nested tree in the sandbox browser, and skips document ingestion and RAG indexing. The control appears only when sandbox, upload, and tool permissions allow it. Limits are 300 files, 200 MiB per folder, and 40 MiB per file; empty directories cannot be selected by the browser. A failed write can leave already written files in the sandbox.

## AI PPT, images, and search

- The optional AI PPT workbench uses Aivory's own creation, outline editing, template selection, deck list, preview, and editing UI. Aivory calls the Docmee API server-side, keeps the API key on the server, and mirrors completed PPTX files into the user's files. Administrators configure it under **Capabilities and integrations > AI PPT**. Group and workspace permission layers govern access; guests cannot use it. Generation and paid edits use the existing credit ledger and usage records. A configured, enabled Docmee integration is required.
- The beta.2 embedded Docmee iframe was removed in beta.3. Beta.5 introduced the current native workbench. The earlier iframe, its browser token flow, and its old configuration location are **not** final 2.5.0 features. Historical beta.2 accounting records remain intact.
- An optional administrator-selected vision-capable model can read attached images for a text-only conversation model and pass structured evidence to it. Native vision models continue to receive images directly. Regular conversations cache image evidence; private chats do not. New vision calls are capped at four per turn, and vision usage can add latency and cost.
- DuckDuckGo joins the existing web-search providers as an explicit, keyless choice. It tries the HTML endpoint and then Lite, filters recognized ads, unwraps redirects, and returns citations. Its public endpoints may challenge or rate-limit server IPs. `auto` still selects a configured keyed provider or SearXNG; it does not silently select DuckDuckGo.

## Chat, knowledge bases, and sign-in

- Message actions are clearer on desktop and mobile, including direct **Fork to new conversation**. Server-targeted actions wait until an optimistic message has a persisted ID. Duplicate pre-tool narration is suppressed, and the five chat-width settings align with their slider stops.
- Stopping a reply now waits for the server's final state before an edited question is sent again. The original opening round can be deleted when its only answer was stopped, while rounds with another answer branch retain deletion protection.
- Knowledge-base selection remains available in chats without project files. The knowledge-base list no longer has the redundant introduction above it; its empty-state and creation guidance remain.
- Login, registration, recovery, and first-run screens share a responsive redesign with labeled fields, localized copy, and theme-aware artwork. Password, OAuth, passkey, two-factor, verification, and reset flows remain available where configured.
- Closing the external AI PPT editor synchronizes changes first. If synchronization fails, the editor stays open and reports the error. Related PPT controls and explanatory copy were simplified.

## Changes accumulated since v2.4.0

The 2.4.x stable releases are part of the v2.4.0 to v2.5.0 comparison, but predate the 2.5 beta series:

- Conversation follow-up queues, branch and generation-state fixes, sandbox browsing, private chat, archive and portability improvements, and Passkey sign-in.
- Workspace permissions, announcements, statistics, email-domain enrollment, and personal-data resolution; administrator-driven stable and prerelease updates.
- Tavily search, public sandboxed HTML preview links, WeCom sign-in, and optional TypeSafe/Jev policies for tool, memory, moderation, and document decisions.
- Retrieval, context, tool-budget, OpenAI Responses, and sandbox reliability fixes; multi-platform application, updater, sandbox runner, and sidecar images for `linux/amd64` and `linux/arm64`.

For release-by-release detail, see [v2.4.9](https://github.com/hjxwz123/Aivory/blob/v2.5.0/docs/releases/v2.4.9.md) and the archived [v2.5.0-beta.1](https://github.com/hjxwz123/Aivory/blob/v2.5.0/docs/releases/v2.5.0-beta.1.md), [beta.2](https://github.com/hjxwz123/Aivory/blob/v2.5.0/docs/releases/v2.5.0-beta.2.md), [beta.3](https://github.com/hjxwz123/Aivory/blob/v2.5.0/docs/releases/v2.5.0-beta.3.md), [beta.4](https://github.com/hjxwz123/Aivory/blob/v2.5.0/docs/releases/v2.5.0-beta.4.md), [beta.5](https://github.com/hjxwz123/Aivory/blob/v2.5.0/docs/releases/v2.5.0-beta.5.md), [beta.6](https://github.com/hjxwz123/Aivory/blob/v2.5.0/docs/releases/v2.5.0-beta.6.md), and [beta.7](https://github.com/hjxwz123/Aivory/blob/v2.5.0/docs/releases/v2.5.0-beta.7.md) notes. ## Upgrade

Back up the database, uploaded files, and generated artifacts. Preserve the deployment's Compose project, `.env`, secrets, ports, and data paths. Database migrations run on startup. AI PPT, the vision bridge, TypeSafe, DuckDuckGo, and sandbox folder tasks are optional and require their respective configuration or permissions.

For a full-stack `deploy/docker-compose.prod.yml` installation, set the deployment's actual `deploy/.env` to:

```dotenv
IMAGE_TAG=2.5.0
UPDATER_IMAGE_TAG=2.5.0
```

Remove or align explicit `APP_IMAGE_TAG` and `SANDBOX_IMAGE_TAG` overrides. Inspect the resolved images with `docker compose --env-file .env -f docker-compose.prod.yml config --images` before pulling and starting them. Personal-profile installations should retain their existing `docker-compose.personal.yml` and `.env.personal` configuration and follow `deploy/README.zh-CN.md`.

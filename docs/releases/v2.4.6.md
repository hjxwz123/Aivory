## What's Changed

Aivory 2.4.6 is a reliability and long-context release. It makes context compaction incremental and observable, keeps document retrieval focused on the active conversation, makes branch switching and stopped generations predictable, and hardens OpenAI Responses replay across mixed OpenAI-compatible gateways. Administrator task models are now independently configurable, while the application and documentation receive the corresponding release and upgrade guidance.

### Long-context compaction

- Reworks compaction around one incremental summary request at a time. Earlier continuation state and newly eligible complete rounds are folded together without repeatedly summarising the same messages.
- Simplifies the administrator surface to the settings that affect actual behaviour: recent-round retention, summary output ceiling, request budget, token trigger, and the optional compaction instruction.
- Retires obsolete target-percent and merge-budget settings and removes them from live settings during migration and backup restore.
- Keeps complete tool envelopes and provider-native evidence available to compaction while retaining shorter canonical previews for ordinary rendering.
- Adds stage-level lifecycle diagnostics for planning, source selection, task execution, persistence, and billing. Logs contain identifiers and measurements, not prompt or document contents.
- Strengthens compare-and-swap persistence and in-flight protection so manual, inline, asynchronous, and multi-instance compaction cannot overwrite one another.

### Retrieval and documents

- Prioritises the active conversation's document when routing retrieval, so a follow-up about the file currently being discussed does not get displaced by a similarly named project document.
- Adds an end-to-end online RAG timeout covering routing, fallback retrieval, embedding/vector work, and full-document summarisation. A timeout fails open to the main chat instead of sending incomplete evidence.
- Preserves branch-local file ownership and prevents uploads or deleted attachments from leaking between sibling conversation branches.

### Conversation branches and generation state

- Paginates the conversation sidebar in small batches and prefetches branch trees only for conversations that need branch navigation, reducing initial payload and switch latency.
- Caches a bounded number of branch trees and serialises branch switches and message deletion reconciliation so late responses cannot clobber a newly selected path.
- Keeps the transcript pinned through delayed layout changes such as citations, images, reasoning traces, and composer height changes, while leaving users reading older messages in place.
- Releases generation state when a conversation or message is deleted and reconciles stopped, rejected, and partially completed generations without leaving stale streaming rows.
- Keeps deleted attachment references visible as unavailable metadata rather than silently showing a broken or unrelated file.

### Administrator task models

- Separates the title-generation and file/tool-route task model policies from the general task model policy.
- Uses the selected conversation model as a conservative fallback when a dedicated task model is unset or unavailable.
- Consolidates administrator overview data loading and surfaces clearer configuration health and activity information.

### OpenAI Responses compatibility

- Replays reasoning, message, function-call, and function-call-output items across tool rounds without dropping `reasoning_text` or `encrypted_content`.
- Keeps provider-native Responses metadata on the first attempt for gateways that support it.
- When a strict OpenAI-compatible gateway rejects a replay before any visible output, retries once with portable item IDs (`msg_`, `rs_`, `fc_`, and hosted-tool prefixes) and removes unsupported replay-only metadata such as `phase` and `logprobs`.
- Recognises non-standard gateways that return an SSE error frame with HTTP 200, so the compatibility retry is not skipped.
- Does not retry after visible text, reasoning, or tool events have been emitted, avoiding duplicated output or tool execution.

### Verification

- Adds regression coverage for incremental compaction, lifecycle diagnostics, RAG timeout and prioritisation, branch isolation, stopped-generation reconciliation, task-model policy resolution, and Responses tool-loop replay.
- Adds strict-gateway coverage for UUID-to-prefixed ID normalisation, `phase`/`logprobs` removal, HTTP 200 SSE errors, encrypted reasoning preservation, and immutable replay history.
- Full backend test suite, `go vet ./internal/llm`, and whitespace validation pass for this release.

### Upgrade notes

- No new mandatory environment variable is required.
- Database migration runs automatically. Existing `files` tables receive the branch-local message column and index; retired compaction settings are removed. Back up the instance before upgrading and allow one instance to finish migration before scaling out.
- If you configured the retired `summary_target_percent` or `summary_merge_max_tokens` settings, replace them with `summary_max_tokens`, `compaction_request_max_tokens`, `compaction_token_trigger`, and `keep_recent_rounds` as appropriate.
- Version-pinned Docker deployments should set `IMAGE_TAG=2.4.6` after the application, sandbox runner, and sandbox sidecar workflows publish matching `linux/amd64` and `linux/arm64` images. Leave `SANDBOX_IMAGE_TAG` unset unless a historical compatibility override is required.
- The internal prompt catalog is documented at <https://docs.aivorygo.com/docs/internal-prompts/overview/>. Runtime administrator and user content remains instance-local and is not part of the public catalog.

### Release scope

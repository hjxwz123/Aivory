# Aivory v2.4.9

`v2.4.9` is the stable release of the 2.4.9 series. It brings together the final functionality from beta.1 through beta.6: TypeSafe/Jev decision policies, smarter tool routing, stronger workspace and domain management, public HTML previews, WeCom sign-in, Tavily search, and Responses compatibility fixes.

This changelog covers all changes since `v2.4.8`, including users upgrading directly from that stable version.

## TypeSafe / Jev decision policies

- Configure TypeSafe channels, API keys and Jev models in administrator settings. Credentials, model versions, prices and policy selections are saved in the database; no TypeSafe environment variables are required.
- Select Jev independently for tool routing, memory deduplication, memory conflict adjudication, content moderation and file routing under **Model policy**.
- File routing covers document-use strategy and selection across multiple documents, including full-document coverage. Retrieval uses the original question; summaries and other text generation continue through chat models.
- A shared decision client supports **Choice**, **Score** and **Noul**, with response validation, bounded timeouts, model-version checks, metadata-only logging, usage accounting and daily token quota handling.
- Uncertain tool decisions retain the full tool set. Uncertain memory decisions avoid merging and mark unresolved conflicts. Uncertain or failed moderation falls back to configured keyword checks; failed document routing falls back to retrieval.
- Decision models stay out of the public chat catalog and policies that require text generation. Configure moderation categories and keywords in moderation settings, then enable model moderation for the relevant chat models.
- Place **Other internal task model** immediately after **Default conversation model** for easier configuration.

Decision thresholds are initial defaults. Integration tests use simulated responses; evaluate real-model accuracy and Chinese-language thresholds against your own deployment's samples. See [TypeSafe configuration and behavior](https://github.com/hjxwz123/Aivory/blob/v2.4.9/docs/typesafe-decisions.md).

## Tool routing, web search and image references

- **Auto** distinguishes focused web-search requests from work requiring the full tool set. Complex investigation, source verification, full-page reading, code execution, file work, image generation or editing, memory writes, named skills and custom tools retain the full resolved tool set.
- Skip the routing model when deterministic full-tool signals or a small tool declaration make an extra decision request unnecessary. A routing failure falls back to the full tool set.
- **Off** allows search-only answering when Aivory search is permitted and configured. Search-only mode supports **up to three search-tool calls**, including batches of independent queries, so the model can refine a search before answering from the available results.
- **Search before answering** requires a search before the final answer when the search-only path is available.
- Add **Tavily** alongside Serper, Brave and SearXNG, with API-key configuration and readiness checks in onboarding and tool settings.
- Include current-turn uploaded reference images in supported image-generation requests, including requests to create a new image.
- Simplify the visible tool selector while retaining its state, counts and accessible labels.

## Domain enrollment and personal data

- Allow up to 50 exact matching domains in a rule. New rules begin automatic enrollment; **Stop automatic enrollment** pauses future automatic enrollment without affecting existing bindings or manual enrollment.
- Let platform administrators manually add eligible active or pending-verification users even when their email does not match the rule. Exclude accounts already bound to another rule, platform administrators and disabled accounts.
- Removing a domain binding preserves independently pre-existing workspace membership.
- Show a personal-data resolution dialog at login when an existing user's personal space becomes locked. Users can download an Aivory ZIP, migrate personal conversations into workspace-private conversations when policy permits, or revisit the action from **Data management**.
- Migration preserves messages, attachments, favorites, archive state and conversation trees, while clearing personal project and knowledge-base associations that cannot cross the workspace boundary. Download remains available when private-conversation migration is prohibited.
- Enforce domain subscription purchase restrictions and add search when selecting initial user groups.

## Workspace profiles, administration and interface

- Let platform administrators configure domain icons and descriptions, and workspace administrators edit their workspace profile. Store profile settings in the database and display the icon beside the workspace name in the sidebar.
- Preserve the dedicated workspace management dialog for administrators, with **General**, members, invites, policy, announcements, audit and statistics. Edit the workspace icon and description under **General**.
- Add **Settings → Work** as a read-only workspace information page for both administrators and ordinary members, with a leave-workspace action only when permitted.
- The members menu opens the management dialog for administrators and **Settings → Work** for ordinary members. Ordinary members cannot browse the workspace member directory.
- Keep current group and credit information visible on the subscription page when workspace subscription purchases are disabled.
- Use the standard information dialog for announcements, with compact action and close controls and a default announcement title when none is configured. Improve announcement scrolling on desktop and mobile.
- Localize announcement editor controls in English, Simplified Chinese, Traditional Chinese, Japanese and French; authored announcement content is not automatically translated.
- Give sandbox browsing, sub-conversations and conversation file drawers a background distinct from the main chat across desktop, mobile, light and dark themes. Align sidebar workspace typography with the rest of the application.

## Public HTML previews

- Create and copy public preview links from completed assistant HTML code blocks or the HTML preview header. Recipients can view the rendered document without signing in.
- Serve the preview document without the application shell. A CSP sandbox and opaque origin isolate it from Aivory cookies, storage and application DOM.
- Use a stable Tailwind runtime URL so shared previews remain renderable across application asset-hash changes.
- Check the publisher's current user-group sharing permission when creating and opening links. Revoking sharing disables existing links.
- Add administrator listing and deletion of public HTML previews, including owner and creation time. Deleted links no longer serve the document.

## Authentication and provider reliability

- Add **Enterprise WeChat / WeCom** OAuth sign-in, including administrator configuration, callback state validation, provider-specific identities, backup and restore support, and localized settings.
- Recover stale registration captcha policies and protect single-use captcha tokens.
- Deduplicate identical streamed reasoning deltas returned simultaneously in `reasoning` and `reasoning_content`.
- Keep Responses commentary out of the final answer.
- When a Responses endpoint rejects a message ID for missing the `msg_` prefix, repair replayed message IDs and retry once on the same channel before recording a failure or selecting a fallback. Handle HTTP validation errors and errors delivered inside an SSE stream.
- Preserve message phase, reasoning state and tool-call associations. Successful repair does not create an Aivory failure usage row or duplicate token accounting; upstream services may still record rejected requests themselves.
- Apply the same repair to the final answer request after the tool execution limit. After the existing 20-round limit, tools remain disabled and the model uses the collected results to answer.
- Keep repair bounded: do not replay requests that already emitted output, and do not invoke channel fallback for repeated message-ID rejection. Other error handling keeps its existing behavior.

## Upgrade and deployment

`v2.4.9` is a stable release and supersedes both `v2.4.8` and the 2.4.9 beta releases. Once the application and updater images finish publishing, administrators can select it in **System update**.

For manual Compose upgrades, set the following in the deployment's existing environment file:

```dotenv
APP_IMAGE_TAG=2.4.9
UPDATER_IMAGE_TAG=2.4.9
```

Use the deployment's existing Compose file and project settings:

```bash
docker compose -f docker-compose.prod.yml pull app updater
docker compose -f docker-compose.prod.yml up -d --no-deps --force-recreate updater app
```

Database migrations, including domain controls and workspace profiles, run automatically on startup. Preserve existing data, deployment settings and credentials. No manual SQL or TypeSafe environment configuration is needed.

# Aivory v2.4.9-beta.5

> Test release / prerelease.

`v2.4.9-beta.5` improves workspace profiles and settings, search-only conversations, subscription visibility and chat drawer styling.

## Workspace profiles and settings

- Administrators can configure domain icons and descriptions; workspace administrators can also edit their workspace icon and description. Profile settings are saved in the database.
- Add a **Work** tab to the settings dialog with the workspace icon, description and a leave-workspace action when permitted.
- Open workspace member management from the **Work** settings tab instead of a separate member dialog. Ordinary members cannot browse the workspace member directory; directory access is restricted to administrators.
- Display the configured workspace icon in the sidebar and align the workspace name with the application's typography.

## Search, subscriptions and announcements

- Allow up to three search-tool calls in search-only mode, so a conversation can refine or retry searches when the first result is insufficient.
- Keep the current group and credit information visible on the subscription page when workspace subscription purchases are disabled.
- Use the standard information dialog for announcements, restore compact action and close controls, and show the default announcement title when no title is configured.

## Interface refinements

- Place **Other internal task model** immediately after **Default conversation model** on the administrator's model policy page.
- Give sandbox browsing, sub-conversations and conversation file drawers a background distinct from the main chat, including desktop/mobile layouts and light/dark themes.
- Keep the sub-conversation composer area consistent with the drawer background while preserving a separate input field surface. The shared HTML preview drawer shell uses the same background treatment.

## Upgrade and deployment

Administrators can select beta.5 in **System update** once its application and updater images have finished publishing. This release is marked as a GitHub prerelease; the stable release remains unchanged.

For a manual Compose update, use the existing deployment environment and set:

```dotenv
APP_IMAGE_TAG=2.4.9-beta.5
UPDATER_IMAGE_TAG=2.4.9-beta.5
```

Then pull and recreate the application and updater with the deployment's existing Compose file:

```bash
docker compose -f docker-compose.prod.yml pull app updater
docker compose -f docker-compose.prod.yml up -d --no-deps --force-recreate updater app
```

Workspace profile database migrations run automatically on startup. Preserve existing deployment settings and data; no manual SQL is required.

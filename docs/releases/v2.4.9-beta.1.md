# Aivory v2.4.9-beta.1

> Test release / prerelease. This is not a stable production release.

`v2.4.9-beta.1` is intended for staging and focused validation. Stable in-app update checks do not select pre-releases. Back up data before testing, do not treat this build as a production automatic update, and expect a later beta or stable release to supersede it.

## What to test

### Automatic tool routing and search-only mode

- **Auto** distinguishes simple, focused web-search requests from work that needs full tools. The lightweight path exposes only optional Aivory web search, permits one query or one batch of independent queries, then finalizes from search-result snippets.
- Complex investigation, source verification, full-page reading, code execution, file work, image creation or editing, memory writes, named skills, and custom tools continue with the full resolved tool set.
- **Off** is now search-only when Aivory search is allowed and configured, rather than unconditionally removing every tool. The optional **Search before answering** setting makes the single permitted search batch mandatory.
- The route model is skipped for deterministic full-tool signals and small resolved tool declarations, avoiding an extra route request where it cannot materially reduce work. A routing failure safely falls back to full tools.

### Domain management

- A rule can contain up to 50 exact matching domains. New rules start automatic enrollment immediately; only a platform administrator manually enabling **Stop automatic enrollment** pauses future automatic enrollment.
- Stopping automatic enrollment does not affect existing bindings or prevent an administrator from manually adding members.
- **Domain users** allows platform administrators to add active or pending-verification users even when their email does not match the rule. Candidates already bound to another rule, platform administrators, and disabled accounts are excluded. Administrators can also remove a member without removing independently pre-existing workspace membership.
- Existing users with personal conversations who become locked receive a personal-data resolution dialog at login. They can download an Aivory ZIP, migrate to workspace-private conversations when policy permits, or ignore the prompt and reopen it later from **Data management** in the avatar menu.
- Migration preserves messages, attachments, favorite/archive state, and conversation trees, while clearing personal project and knowledge-base associations that cannot cross the workspace boundary. When private conversations are prohibited, downloading remains available and migration is unavailable.

### Workspace announcements and tool selector

- Workspace announcement editor controls now follow the administrator UI language in English, Simplified Chinese, Traditional Chinese, Japanese, and French. Announcement content remains authored content and is not automatically translated for recipients.
- The visible explanatory copy was removed from the conversation tool entry, Auto/On/Off rows, and Choose Tools heading while retaining names, state, counts, and accessible labels.

### Uploaded image references

- Current-turn uploaded reference images are included in supported image-generation requests, including generation requests that create a new image rather than editing an existing one.

## Upgrade and deployment

- Back up the database, uploaded files, and generated artifacts before testing.
- Test with a non-production or staging deployment first. Validate domain policy, automatic/manual enrollment, personal-data download or migration, and workspace announcements with representative accounts.
- The exact prerelease tag is `2.4.9-beta.1`. It is distinct from the stable `2.4.9` release line, which this release does not create.
- For a Docker deployment using the updater, set the application and updater to the same test tag:

```dotenv
APP_IMAGE_TAG=2.4.9-beta.1
UPDATER_IMAGE_TAG=2.4.9-beta.1
```

- Do not replace an existing deployment environment file with an example. Preserve the existing Compose project name, data paths, database credentials, host ports, and secrets.

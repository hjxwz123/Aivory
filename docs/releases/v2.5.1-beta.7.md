# Aivory v2.5.1-beta.7

> Test release / prerelease with a new desktop client and automated Windows, Linux, and macOS installer builds.

This release introduces the Electron desktop client, browser sign-in authorization,
administrator-managed desktop updates and download links, and responsive layout
fixes for web and desktop. It also includes the borderless nested input fixes
published after beta.6.

## Desktop Installers

GitHub Actions builds installers from this release tag on native Windows, Linux,
and macOS runners. All four platform builds have completed successfully, and the
installers are attached to this release together with `SHA256SUMS.txt`.

| Operating System | Architecture | Installers |
| --- | --- | --- |
| Windows | x64 | `Aivory-2.5.1-beta.7-win-x64.exe` |
| Linux | x64 | `Aivory-2.5.1-beta.7-linux-x64.AppImage`, `Aivory-2.5.1-beta.7-linux-x64.deb` |
| macOS | Apple Silicon / arm64 | `Aivory-2.5.1-beta.7-mac-arm64.dmg`, `Aivory-2.5.1-beta.7-mac-arm64.zip` |
| macOS | Intel / x64 | `Aivory-2.5.1-beta.7-mac-x64.dmg`, `Aivory-2.5.1-beta.7-mac-x64.zip` |

Official installers start with an empty server address. Enter your deployed
Aivory website's root URL on first launch; the client saves it locally and retains
it through updates. Builders can still set a default server with
`AIVORY_DESKTOP_BASE_URL`. These test installers are unsigned, so your operating
system may display an application source or signature warning.

## Desktop Features

- Use the same frontend and backend as the web app, including conversations, streaming responses, files, settings, and administration.
- Closing the main window minimizes it and preserves the taskbar or Dock icon. Use the icon menu to quit the application.
- Display the Aivory icon in the macOS menu bar and the Windows or Linux system tray.
- Show a local network status screen while offline, then return to the loaded page and preserved drafts when connectivity recovers.
- Offer browser authorization and administrator-enabled password login on the desktop login page. Third-party and passkey sign-in remain available through the system browser, followed by desktop authorization.
- Build the browser authorization URL from the saved server address and protect the flow with S256 proof and short-lived, single-use credentials.
- Hide the desktop login form's welcome heading and subtitle while retaining two-factor verification instructions. Use the product UI font on the authorization page.
- Identify desktop clients in login history, feedback, audit records, and active sessions.

## Administrator-Managed Updates and Download Links

- Add **Admin → System → Desktop client** at `/admin/settings/desktop`.
- Let administrators select published official installers or configure a custom version and download URLs for each operating system and architecture.
- Prompt desktop users to update only when the administrator has enabled publication and a newer installer is available for their platform.
- Keep the update prompt simple: announce a new version and ask whether to update. Accepting opens the appropriate installer URL.
- Configure the **Download App** URL and visibility independently of update publication. The URL can point to a download page or a direct installer link.
- Display the download link at the top-left of the web new-conversation welcome screen and in the avatar menu. Hide both links in native desktop clients.
- Support English, French, Japanese, Simplified Chinese, and Traditional Chinese throughout the new interfaces and prompts.

## Web Layout Fixes

- Fit page shells to the available window height and scroll long content within its own pane across chat, administration, the resource library, files, knowledge bases, projects, subscriptions, sharing, legal pages, and welcome screens.
- Adapt login and registration forms to narrow screens, short windows, and longer translated text, fixing horizontal page overflow.
- Keep home corner controls compact and prevent overlap between the download link, private-mode control, and avatar.
- Improve the visibility of borderless nested inputs while preserving the product's minimal use of lines.

## Upgrade and Deployment

Deploy the matching frontend and backend together to enable browser authorization
and desktop updates. Existing user settings, server addresses, and sessions
continue to use their existing storage. No new database tables or required Redis
service are introduced. Older servers without the desktop update endpoint do not
provide update prompts.

The release images have been built and published under `ghcr.io/hjxwz123`:
`aivory-app`, `aivory-updater`, `aivory-sandbox`, and `aivory-sandbox-sidecar`,
each tagged `2.5.1-beta.7` with support for `linux/amd64` and `linux/arm64`.
Select this test release in the administrator system update page, or set the
following values in `deploy/.env`:

```dotenv
IMAGE_TAG=2.5.1-beta.7
UPDATER_IMAGE_TAG=2.5.1-beta.7
```

Align any explicit `APP_IMAGE_TAG` or `SANDBOX_IMAGE_TAG` overrides, then deploy:

```bash
cd deploy
docker compose --env-file .env -f docker-compose.prod.yml pull
docker compose --env-file .env -f docker-compose.prod.yml up -d --no-build
```

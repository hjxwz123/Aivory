# Aivory v2.5.1-beta.7

> Test release / prerelease — 新增桌面客户端，以及 Windows、Linux、macOS 自动构建与发布。

本次测试版包含 Electron 桌面客户端、浏览器登录授权、管理员管理桌面更新与下载入口、
网页及桌面布局修复，以及 beta.6 发布后的无边框嵌套输入控件修复。

## 桌面安装包

GitHub Actions 使用本次版本标签的代码，在各系统的原生构建环境中生成安装包，
全部构建成功后自动上传到此 Release，并提供 `SHA256SUMS.txt` 校验文件。

| 系统 | 架构 | 安装包 |
| --- | --- | --- |
| Windows | x64 | `Aivory-2.5.1-beta.7-win-x64.exe` |
| Linux | x64 | `Aivory-2.5.1-beta.7-linux-x64.AppImage`、`.deb` |
| macOS | Apple Silicon / arm64 | `Aivory-2.5.1-beta.7-mac-arm64.dmg`、`.zip` |
| macOS | Intel / x64 | `Aivory-2.5.1-beta.7-mac-x64.dmg`、`.zip` |

官方安装包不内置示例服务器。首次启动填写自己部署的 Aivory 网站根地址；地址持久保存
在本地，后续更新沿用已有设置。构建者仍可通过 `AIVORY_DESKTOP_BASE_URL` 设置默认地址。
这是未签名的测试安装包，系统可能显示应用来源或签名提醒。

## 桌面功能

- 与网页版使用同一套网页和服务端，支持对话、流式输出、文件、设置与管理后台。
- 关闭主窗口只最小化，保留任务栏 / Dock 图标；图标菜单提供真正退出。
- macOS 菜单栏、Windows / Linux 系统托盘使用 Aivory 图标。
- 离线显示本地网络状态界面，恢复连接后继续使用已加载的页面与草稿。
- 桌面登录只显示浏览器授权和管理员允许的账号密码登录，不在桌面页面显示第三方登录
  或通行密钥入口；第三方登录可通过系统浏览器完成后授权桌面应用。
- 浏览器授权网址由当前服务器地址决定，使用 S256 校验与短期一次性凭据。
- 桌面登录表单隐藏欢迎标题和副标题，保留二次验证说明；授权页面使用产品界面字体。
- 登录记录、反馈、审计记录和活动会话能够识别“App 版”。

## 管理员更新与下载入口

- 新增 **管理后台 → 系统 → 桌面客户端**，地址 `/admin/settings/desktop`。
- 管理员可选择已发布的官方安装包，或填写自建安装包的版本及各系统、架构的下载地址。
- 只有管理员开启发布，且当前系统存在更高版本安装包时，桌面客户端才提示更新。
- 用户更新提示简化为发现新版本和是否更新；点击后打开对应安装包地址。
- 可独立配置“下载 App”网址与显示开关，网址支持下载页面或安装包直链。
- 网页版新对话欢迎页左上角和头像菜单显示下载入口；桌面版隐藏两个入口。
- 新增界面与提示支持简体中文、繁体中文、英文、日文、法文。

## 网页布局修复

- 页面外壳适应窗口高度，长内容在相应区域内滚动，覆盖聊天、管理后台、资源库、文件、
  知识库、项目、订阅、分享、法律页面和欢迎页面。
- 登录与注册表单处理窄屏、低窗口高度和长语言文案，修复整体左右溢出。
- 首页角落操作保持紧凑，不与下载入口、隐私模式按钮或头像重叠。
- 修复无边框嵌套输入控件辨识度，保留少线条的产品设计。

## 升级部署

浏览器授权及桌面更新需要一起部署新版网页和后端。已有用户配置、服务器地址和会话
继续使用现有存储；没有新增必需的数据库表或 Redis 服务。旧服务器缺少桌面更新接口时
不会提供更新提示。

本次标签触发既有 Docker 构建流程，发布 `ghcr.io/hjxwz123` 下的 `aivory-app`、
`aivory-updater`、`aivory-sandbox`、`aivory-sandbox-sidecar`，版本为 `2.5.1-beta.7`，
支持 `linux/amd64` 和 `linux/arm64`。镜像发布完成后可在后台选择该测试版，或在
`deploy/.env` 配置：

```dotenv
IMAGE_TAG=2.5.1-beta.7
UPDATER_IMAGE_TAG=2.5.1-beta.7
```

如果存在单独的 `APP_IMAGE_TAG` 或 `SANDBOX_IMAGE_TAG`，请同步调整。部署命令：

```bash
cd deploy
docker compose --env-file .env -f docker-compose.prod.yml pull
docker compose --env-file .env -f docker-compose.prod.yml up -d --no-build
```

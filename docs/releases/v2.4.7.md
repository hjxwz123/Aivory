## What's Changed

Aivory 2.4.7 is the privacy and access release. It ships a fully ephemeral private chat channel with an anonymous usage pipeline, optional passkey (WebAuthn) login with self-service device management, complete conversation export and archive tooling, provider compatibility hardening for Gemini and strict OpenAI Responses gateways, and a faster batched document retrieval path. The application also receives the new traced brand lockup, administrator channel-model refresh, and first-render browser language inheritance.

### Private chat (ephemeral channel)

- Adds a dedicated private channel: messages, reasoning, images, and drafts live only in React state — never in the conversation store, localStorage, IndexedDB, or the sidebar — and are destroyed on refresh, exit, or page hide.
- Renders the private conversation with the exact normal-chat UI: same bubbles, model headers, reasoning trace, hover action bar (copy / regenerate / edit-and-resend, all in-memory), composer, and centered start screen, without touching any normal-chat component.
- Images stay as in-memory data URLs end to end; the normal file-upload path is never used. Answers render through a dedicated markdown renderer that blocks remote images, HTML, and Mermaid execution.
- Server side: signed `POST /api/private-chat` with no-replay SSE, client-mirrored history validation, provider request bodies stripped of caching and tooling fields, and billing/usage logs fully anonymized (private message IDs, blanked conversation and request metadata, fixed anonymous title in admin views).
- Fixes non-OpenAI private requests: Anthropic and Google channels now receive the administrator-configured output cap (falling back to a conservative 8192) instead of the 64000 provider default that real Claude/Gemini endpoints reject with 400.

### Passkey login (WebAuthn)

- Optional, per-user passkeys mirroring the 2FA shape: register devices (fingerprint, face, or device PIN) under Settings → Account, then sign in from the login page without any password.
- Usernameless discoverable-credential login with user verification required; signature counters are persisted for clone detection; credential-owner binding is enforced via the user handle; login failures return a single generic code to prevent account enumeration; one-shot five-minute challenge tickets burn after repeated failures.
- A passkey is a complete authentication factor — passkey logins do not additionally require TOTP, and the password + 2FA path is unchanged.
- Administrators can toggle passkey login globally in the registration policy page; the policy is exposed through the public auth-policy endpoint and gates every passkey surface.
- All passkey and private-chat strings ship in English, Simplified Chinese, Traditional Chinese, Japanese, and French, guarded by locale-parity tests.

### Conversation portability and archives

- Export conversations as complete JSON batches and as ZIP archives, with large archive imports processed in batches to stay within request limits.
- Archived conversations open as read-only transcripts, preserving full content without allowing mutation.

### Authentication and request-proof hardening

- Enforce authenticated request proofs consistently across surfaces that previously accepted unsigned session calls.
- Strip unsupported Responses replay `logprobs` metadata before requests, avoiding strict-gateway rejections.
- Raise the moderation model output token budget so long verdicts no longer truncate into misclassification.

### Providers, retrieval, and performance

- Handle fragmented Gemini tool calls: partial `functionCall` chunks are reassembled correctly, and fallback channels engage on upstream protocol failures.
- Batch and parallelize document retrieval, cutting follow-up latency on multi-document conversations.
- Skip RAG routing entirely for projects without content, avoiding pointless embedding work.

### Administrator and operations

- Fetch newly published models from saved channels directly, so gateway-side model additions no longer require re-entering credentials.
- Align the backup page with the admin settings layout, and compact and polish the settings UI surface.

### Interface

- New traced Aivory brand lockup across the app with unified loading fallbacks and packaged logo assets, refreshed About and resource pages, and a rebalanced project detail layout.
- The initial page now inherits the browser language on the very first render (`zh-CN` / `zh-TW` / `en-US`-style tags are normalized before i18next validation), while an explicit language choice still wins.
- Project instruction text spans the full content width.
- README gains enterprise SSO/OAuth2 and MCP integration sections.

### Upgrade notes

- The `passkeys` table is created automatically on startup (idempotent migration); no manual action required.
- The WebAuthn dependency raises the module's Go directive to 1.26; `deploy/Dockerfile.app` now builds on `golang:1.26-bookworm`. Source builds need Go 1.26+, and networks without access to `proxy.golang.org` should set `go env -w GOPROXY=https://goproxy.cn,direct` once.
- Passkeys require a secure context: HTTPS, or `localhost` for development. Plain-HTTP LAN deployments simply hide all passkey affordances.
- Private chat is reached from the shield button on the chat home page; nginx deployments that front `/api/private-chat` should disable request body buffering and access logging for that location (see `docs/private-chat.md`).
- Version-pinned Docker deployments should set `IMAGE_TAG=2.4.7` after the application, sandbox runner, and sandbox sidecar workflows publish matching `linux/amd64` and `linux/arm64` images.

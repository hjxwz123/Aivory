# Aivory v2.5.1-beta.5

> Test release / prerelease.

This release brings together the administrator table redesign, quieter shared UI, conversation and link settings, expanded audit logs, and channel/model scheduling changes. It includes all 285 pending files from the work following beta.4, published in five feature batches before this release preparation commit.

## Administrator Tables and Layout

- Use one shared table component with visible headers, compact rows, consistent actions, and horizontal scrolling that preserves all columns.
- Reduce decorative borders and dividers across administrator pages, settings, tables, and shared controls. Align header actions, button sizes, segmented switchers, and image-style save controls.
- Add inline filters or search for channels, models, domains, workspaces, user groups, and redeem codes.
- Make the application logo follow light/dark mode and the selected color theme. Reuse it in the administrator console with a localized administrator label.
- Show token usage, spending, registration, and activity trends on the configured administrator overview.

## Audit and Logs

- Group call logs and audit logs under **Audit and Logs**. Redirect the previous `/admin/usage` page to `/admin/logs/usage` and add `/admin/logs/audit`.
- Keep log tables focused on summary fields; open request details and errors in a right-side drawer. Include first-token latency and total duration in call logs.
- Expand audit coverage beyond workspace operations, including administrator changes and authentication events. Ordinary administrator page views do not create audit events.
- Include log IDs, actor and target information, request metadata, outcome, and redacted change evidence. Support filtering by type and other audit fields, export, individual deletion, and deletion of filtered results with a cutoff boundary.
- Use side drawers for user information, conversation lists, login history, and memory inspection.
- Include the updated audit and routing API registrations and their existing regression coverage. Correct missing payment-order status translations.

## Channels and Model Scheduling

- Configure custom JSON request headers on a channel and forward them to its upstream requests.
- Discover or manually configure each channel's supported actual request IDs. Limit regular and fallback channel selection to channels that support the model's request ID.
- Bind a model to multiple regular and fallback channels. Lower numbers have higher priority; regular channels at the same priority share traffic according to weight, while fallback channels are tried in priority order.
- Configure first-token timeouts per model. Add consecutive error and timeout thresholds that temporarily disable a channel either for one model or across all models using that channel.
- Expose temporary-disable status, affected models, expiry, and manual recovery. A manually closed channel remains visible in model bindings and does not participate in scheduling.
- Put the actual request ID first in model basics, keep icons and descriptions in basics, and split advanced options into focused tabs and collapsible sections.
- Give channel creation and editing matching layouts and dimensions. Align binding removal controls and place recovery/status controls below the selector.
- Put priority/weight explanations beside their controls and keep the separate cache guidance recommending upstream NewAPI or sub2api routing.

## User Settings and Shared UI

- Move archived conversations from the avatar menu into **Conversations and Links** settings, alongside shared conversations and HTML preview link management.
- Support dragging sidebar history entries to persist their order through conversation update timestamps.
- Widen the desktop avatar menu, compact file attachment chips, and align settings buttons with their text.
- Apply the quieter surface treatment to chat, files, knowledge bases, projects, presentations, account settings, subscriptions, and other shared overlays.
- Include updated English, French, Japanese, Simplified Chinese, and Traditional Chinese translations.

## Compatibility

- Add SQLite and PostgreSQL storage migrations for channel/model bindings, health state, audit evidence, and usage timing.
- Backfill existing single-channel and fallback configurations into the new routing tables and retain compatibility with legacy channel fields and older imported model rows.
- Deploy the updated frontend and backend together; the application image contains both. Keep a database backup when upgrading this test release because it introduces schema changes.
- No new package dependencies or required Redis service are introduced by these changes.

## Validation

- No additional code tests, lint checks, type checks, or local builds were run during this release preparation, as requested.
- Existing frontend, browser, and Go regression test files from the implementation are included in the corresponding feature commits.
- GitHub Actions builds and publishes the release containers through the existing publishing workflows. Build publication does not replace application regression testing.

## Upgrade

After all four images for this tag finish publishing, administrators can select beta.5 in **System update**. For a manual Compose upgrade, set `deploy/.env` to:

```dotenv
IMAGE_TAG=2.5.1-beta.5
UPDATER_IMAGE_TAG=2.5.1-beta.5
```

Remove or align any explicit `APP_IMAGE_TAG` or `SANDBOX_IMAGE_TAG` overrides, then deploy:

```bash
cd deploy
docker compose --env-file .env -f docker-compose.prod.yml pull
docker compose --env-file .env -f docker-compose.prod.yml up -d --no-build
```

The tag triggers publication of `aivory-app`, `aivory-updater`, `aivory-sandbox`, and `aivory-sandbox-sidecar` under `ghcr.io/hjxwz123`, each tagged `2.5.1-beta.5` for `linux/amd64` and `linux/arm64`.

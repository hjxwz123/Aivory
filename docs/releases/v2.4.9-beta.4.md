# Aivory v2.4.9-beta.4

> Test release / prerelease.

`v2.4.9-beta.4` adds administrator-managed TypeSafe/Jev decisions for tools, memory, moderation and document routing. It also improves registration, domain subscription controls, workspace announcements and OpenAI Responses output handling.

## TypeSafe / Jev decision policies

- Add a TypeSafe channel and API key in channel administration, then discover or create Jev decision models. Credentials, model versions, prices and policy selections are saved in the database; no TypeSafe environment variables are used.
- Select Jev independently for tool routing, memory deduplication, memory conflict adjudication, content moderation and file routing under **Model policy**.
- File routing combines document-use strategy with multiple-document selection for full-document coverage. Jev uses the original question for retrieval; summaries and other text generation continue through chat models.
- The shared client supports Choice, Score and Noul, with validated responses, bounded timeouts, model-version checks, metadata-only logs, usage accounting and daily token quota handling.
- Uncertain tool decisions retain the full tool set. Uncertain memory decisions avoid merging and mark unresolved conflicting facts accordingly. Uncertain or failed moderation falls back to the configured keyword checks. Failed document routing falls back to retrieval.
- Decision models are excluded from the public chat catalog and from policies that require text generation.
- Configure moderation categories and keywords in moderation settings, and enable model moderation on each chat model that should use it.

Decision thresholds are initial defaults. Integration tests use simulated API responses; real-model accuracy and Chinese-language thresholds still require evaluation on deployment-specific samples. See [TypeSafe configuration and behavior](https://github.com/hjxwz123/Aivory/blob/v2.4.9-beta.4/docs/typesafe-decisions.md).

## Registration, domains and workspace announcements

- Recover stale registration captcha policies and guard single-use captcha tokens.
- Enforce domain subscription purchase restrictions and improve selection of initial user groups with search.
- Improve workspace announcement layout and scrolling on desktop and mobile.
- Include database migrations and translations for the updated domain controls.

## Provider output and documentation

- Keep OpenAI Responses commentary out of the final answer.
- Refresh the bilingual README layout and brand headers.

## Upgrade and deployment

Administrators running beta.2 or beta.3 can select beta.4 in **System update** once its application and updater images have finished publishing. This release is marked as a GitHub prerelease; the stable release remains unchanged.

For a manual Compose update, use the existing deployment environment and set:

```dotenv
APP_IMAGE_TAG=2.4.9-beta.4
UPDATER_IMAGE_TAG=2.4.9-beta.4
```

Then pull and recreate the application and updater with the deployment's existing Compose file:

```bash
docker compose -f docker-compose.prod.yml pull app updater
docker compose -f docker-compose.prod.yml up -d --no-deps --force-recreate updater app
```

Database migrations run automatically on startup. Preserve existing deployment settings and data; no manual SQL or new TypeSafe environment variables are required.

# Aivory v2.5.1-beta.2

> Test release / prerelease.

This release makes the chat home's initial loading state stable and adds an explicit loading indicator to sidebar history. It also includes independent code-block wrapping controls and an account default that is saved across devices.

## Chat Home and Model Selection

- Reserve space for recent conversations and show a subtle skeleton while they load. Loaded conversations fade in without moving the composer; an empty history keeps the layout stable, and a failed request offers a retry.
- Give the model picker a stable width and a loading skeleton instead of briefly showing the generic `Model` placeholder. Model loading errors and an empty catalog have explicit states.
- Make chat models available as soon as their catalog loads, without waiting for optional image models and tag metadata. Workspace and policy changes cannot reuse a stale selection.
- Wait for image models before selecting a drawing model, and enable sending only when the selected model is ready.
- Respect reduced-motion preferences and provide loading and retry messages in all five supported languages.

## Sidebar History

- Show a spinner and a loading message while the initial workspace and conversation history are loading, and when switching workspaces.
- Fade the history into view once it is ready. Keep the current list visible during a refresh of the same workspace to avoid unnecessary flicker.
- Distinguish loading, empty history, and errors, with a retry action for failed requests. Hidden loading content cannot receive keyboard focus.

## Code-Block Wrapping

- Add an independent wrapping switch to each code block, including nested Markdown blocks and private chat. A manually changed block can be reset to follow the default.
- Add **Default code-block wrapping** in Settings > Appearance. The default is off; signed-in users save the preference to their account, while signed-out users keep it in the current browser.
- Refresh the account preference on login, page reload, entry to Appearance settings, and return to the foreground. Failed saves roll back with a message, and stale responses cannot override another account's settings.
- Preserve each block's selection during streaming and final syntax highlighting. Individual overrides last for the current block's display lifecycle; a reload or account change restores inheritance.
- Wrapping changes presentation only. Copying, running Python, previewing HTML, and sharing continue to use the original code.

## Compatibility

- This release adds no database migrations. The wrapping default uses the existing user-settings storage.
- The application image includes both the updated API and frontend so the new wrapping preference can be saved. Older clients remain compatible with the new setting.
- Existing Deep Research, speech recognition, and AI PPT pricing behavior from beta.1 is retained.

## Validation

- The synchronized application passed all 894 frontend tests across 151 test files, TypeScript checks, and a production build.
- Home and sidebar loading states were checked in a real browser, including narrow layouts, workspace switches, empty history, retry states, and cached refreshes.
- The code-block wrapping changes include API and storage regression checks and five groups of real-browser checks covering wrapping, original-code copying, final highlighting, keyboard interaction, HTML preview, and narrow layouts.

## Upgrade

Set the deployment's `deploy/.env` to the new test version after all four images for this tag finish publishing:

```dotenv
IMAGE_TAG=2.5.1-beta.2
UPDATER_IMAGE_TAG=2.5.1-beta.2
```

Remove or align any explicit `APP_IMAGE_TAG` or `SANDBOX_IMAGE_TAG` overrides, then verify and deploy:

```bash
cd deploy
docker compose --env-file .env -f docker-compose.prod.yml config --images
docker compose --env-file .env -f docker-compose.prod.yml pull
docker compose --env-file .env -f docker-compose.prod.yml up -d --no-build
```

The release publishes `aivory-app`, `aivory-updater`, `aivory-sandbox`, and `aivory-sandbox-sidecar` under `ghcr.io/hjxwz123`, each tagged `2.5.1-beta.2` for `linux/amd64` and `linux/arm64`.

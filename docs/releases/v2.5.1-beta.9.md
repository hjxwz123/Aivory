# Aivory v2.5.1-beta.9

> Test release / prerelease with model-owned request protocols, more reliable inline UI, and administrator usability fixes.

## Administrator UI and Localization

- Use consistent side drawers for administrator create/edit forms. Actions follow the form content instead of occupying a pinned footer.
- Translate audit operations, target types, actor roles, and configuration change fields in English, Simplified Chinese, Traditional Chinese, Japanese, and French. Model skill/channel changes now show readable labels; stable action identifiers remain available in the detail drawer.
- Show model display names in the user conversation list instead of internal IDs. The administrator API includes `model_label`, resolves disabled models, and uses the upstream request ID if the display name is empty. Removed models show an unavailable state; older servers remain supported through a single model-catalog lookup.
- Replace the notification checkbox and Close controls with one **Don't show these again** action. It saves dismissal for the current publication, preserves unread history, and allows new or edited notifications to appear. Failed saves keep the dialog open for retry.
- Present the home **Download App** entry as a plain link.

## Model-Owned Request Protocols

- Configure the provider and request format on each model. All scheduled channels for the same model use its protocol; a timeout fallback to another model uses that model's protocol.
- Support OpenAI Chat Completions, OpenAI Responses, Anthropic Messages, Gemini GenerateContent, OpenAI Images, OpenAI Embeddings, native DashScope Embeddings, and TypeSafe decisions according to model kind.
- Migrate existing models from their original primary channel format without overwriting an explicit model protocol. Retain legacy columns and support imports from older configuration archives.
- Preserve priority-based channel retries and the global first-visible-content timeout configured in **Model policy**.
- Preserve Aliyun's OpenAI-compatible endpoint behavior: a Base URL ending in `/compatible-mode` continues to use `/compatible-mode/v1/embeddings`. Existing deployment URLs do not need to change.

The database migration is additive, but older executables do not implement model-owned protocol routing. Coordinate server and desktop upgrades when changing model protocols.

## Skills and Generative UI

- Make the permitted built-in presentation skill available proactively when charts, comparisons, timelines, or interactive explanations help the answer, while respecting administrator enablement and permission boundaries.
- Deduplicate model-bound, explicitly selected, and tool-loaded skills, including fallback-model turns. Preserve administrator edits when refreshing untouched built-in skill instructions.
- Stream inline HTML only when script, style, and tag boundaries are complete; keep the last working preview during partial updates and flush completed content promptly.
- Show compact loading, error, and retry states instead of leaving a blank frame indefinitely. Recover when asynchronous content becomes ready and avoid unnecessary iframe reloads.
- Remove **View source** controls from inline generated interfaces. Existing opaque-frame isolation and network/native access restrictions remain enforced.

See the [Generative UI guide](https://github.com/hjxwz123/Aivory/blob/v2.5.1-beta.9/docs/generative-ui.md) for formats and trigger examples.

## Jev / TypeSafe Diagnostics

- Record request method, URL, sanitized headers, optional request body, elapsed time, and sanitized upstream error responses in administrator call logs.
- Capture validation failures even when the upstream response is HTTP 200. Keep request/response payloads out of public errors and console logging.
- Respect request-body logging settings and private-conversation redaction. Successful request details are saved only when full logging is enabled.

## Desktop Installers and Images

GitHub Actions builds the release tag on native runners, verifies bundled frontend/runtime files and installer names, and attaches all packages with `SHA256SUMS.txt` after every platform build succeeds.

| Operating system | Architecture | Packages |
| --- | --- | --- |
| Windows | x64 | `Aivory-2.5.1-beta.9-win-x64.exe` |
| Linux | x64 | `Aivory-2.5.1-beta.9-linux-x64.AppImage`, `Aivory-2.5.1-beta.9-linux-x64.deb` |
| macOS | Apple Silicon / arm64 | `Aivory-2.5.1-beta.9-mac-arm64.dmg`, `Aivory-2.5.1-beta.9-mac-arm64.zip` |
| macOS | Intel / x64 | `Aivory-2.5.1-beta.9-mac-x64.dmg`, `Aivory-2.5.1-beta.9-mac-x64.zip` |

Official installers bundle the frontend locally and ask for a server URL on first launch. Existing server settings persist through app updates. This release also fixes empty Apple-signing secrets being interpreted as certificate paths. macOS packages receive signature verification; these test builds use ad-hoc signing unless Developer ID credentials are configured and are not Apple-notarized without those credentials.

Multi-architecture `linux/amd64` and `linux/arm64` application and updater images:

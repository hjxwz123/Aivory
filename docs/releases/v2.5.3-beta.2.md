# Aivory v2.5.3-beta.2

Second test release of the 2.5.3 series. This release adds a personal Usage page and daily check-in, introduces six illustrated themes, and improves generative UI, long messages, and private chat. It includes the context compaction, edit-and-resend, conversation deletion, and request signature fixes from **v2.5.3-beta.1**.

## Personal Usage and Daily Check-in

- Open **Usage** below **Subscription** in the account menu. This page shows timed and permanent credit balances. The Subscription page continues to show the user's current group and subscription details.
- Switch the 365-day activity heatmap between tokens used and credits spent. Select a day to inspect its totals. The heatmap uses the active theme's colors.
- Select today's calendar cell to check in. Successful claims show the reward with an animation. Browse previous months to review the credits granted on each check-in date.
- Administrators can enable check-in, set a fixed reward or an inclusive random range, and choose timed or permanent credits. The server awards at most one check-in per user per system day, including when requests arrive concurrently.
- Active timed check-in rewards contribute to the timed credit total. The Usage page shows the user's group allowance and remaining group credits separately from check-in rewards. Charges spend expiring check-in credits first, then the group allowance, then permanent credits. Timed check-in rewards expire at the next system-day boundary.

## System Time and Quotas

- Configure the system time zone in **Admin > Credits** with an IANA name such as `Asia/Shanghai`. Existing installations use UTC until an administrator changes the setting. The Usage page presents the resulting calendar dates without a time-zone label.
- The configured zone determines check-in days, daily activity totals, daily token and default image quota boundaries, and monthly workspace creation limits. Whole-day group credit cycles retain their local refresh time across daylight-saving changes.
- Backup and import support the new settings and check-in records.

## Illustrated Appearance and Private Chat

- Choose from **Pottery studio**, **Blue Note**, **Star atlas**, **Afternoon post**, **Deep-sea expedition**, and **Silver darkroom**. Each programmatically hand-drawn scene uses a matching accent palette. Switching back to the plain theme restores the previously selected accent.
- Several scenes use full-page artwork on the chat homepage. Sidebars, new-chat composers, dialog headers, and selected empty states use matching details. Sidebar artwork uses the space below the history list and hides when space runs out, keeping menu positions and history scrolling consistent.
- Active conversations use a quiet, neutral background for reading. Private mode uses a transparent eye icon that changes shape when active, a compact model selector, and an unfilled privacy label.
- Composer focus uses a tonal change and a soft shadow. Composer positions and sizes stay fixed when gaining focus. Success notifications now use a theme-colored sparkle, and the previous green UI accents have been replaced.

## Generative UI and Long Messages

- Render Markdown in generative UI text and paragraph blocks, including headings, lists, tables, and inline formatting. Keep Markdown code and math intact while evaluating prose bindings such as conditional expressions that update with a control.
- Improve inline math detection around Chinese characters and currency amounts.
- Fold long user messages after six lines on desktop and four on phones. Expand and collapse with a height animation that respects reduced-motion preferences.

## Upgrade Notes

- Deploy the frontend and API together. Server startup creates the check-in table on supported SQLite and PostgreSQL installations. Daily rewards are opt-in and can be enabled from the credit settings.
- Check the system time zone before enabling check-in or changing daily boundaries for an existing deployment.
- This is a GitHub prerelease. **v2.5.2** remains the latest stable release. Deployment administrators can offer this test version under **Admin > System > Desktop Client** after the matching installers are attached.

## Validation

- Production frontend build with TypeScript checking passed. The full frontend suite on Node 22 had 1,277 passing tests and the same 38 failures as the preceding main commit.
- Passed focused browser checks for generative Markdown and conditional bindings in ordinary and private chat, 45 reply and message-folding scenarios, five layout viewports, and interactive checks for Usage, check-in, illustrated themes, and private chat. The broader generative UI suite hit a Chromium frame-blocking error in its navigation fixture.
- Go store and tools suites passed, as did targeted checks for concurrent claims, reward expiry and spending order, local calendar boundaries, usage history, quota reservations, and appearance settings. Broader API and LLM runs reported failures in existing audio, tool routing, and compaction test cases that were also reproduced on the preceding main commit.

# Aivory v2.5.1-beta.6

> Test release / prerelease.

This release unifies model channels into a priority queue, restores one global first-byte timeout in Model policy, and improves administrator navigation and model picker sizing. It includes the three feature commits published after beta.5.

## Channel Scheduling

- Configure all channels for a model in one priority queue. Lower numbers are tried first; weights distribute the first choice among channels at the same priority.
- If a request fails before displaying content, try the remaining channels at that priority and then later priorities. Keep the successful channel for subsequent requests in the same turn.
- Forward the first visible text, thinking, or tool event immediately. Once the current upstream request has displayed content, do not replay it on another channel after a failure.
- Apply the priority queue to chat, internal model calls, and image generation. Attribute request logs and health counters to the channel that actually handled each attempt.
- Fold older fallback channel bindings into the queue after existing regular priorities. Retain legacy fields and API payload compatibility for older configurations and clients.

## Global First-Byte Timeout

- Set the timeout for all models at `/admin/settings/model-policy`. Remove the individual model timeout control and ignore its legacy value during request scheduling.
- Preserve the existing measurement: start immediately before the upstream HTTP request and stop at the first response-body byte, excluding local retrieval and request preparation.
- Keep timeout model fallback separate from ordinary channel failure retries. A configured timeout fallback model takes over when the original request returns no bytes before the threshold.
- Use the global threshold for model-level and channel-wide consecutive-timeout auto-disable rules. A value of zero disables timeout monitoring; timeout rules cannot be newly configured while it is zero.
- Without a timeout fallback model, an enabled auto-disable rule observes a late first byte without cancelling the current response.

## Interface

- Increase administrator sidebar item spacing, icon-to-text spacing, and spacing between top navigation options. Increase top navigation text from 12px to 13px.
- Size the model picker to its selected name instead of reserving a fixed 180px width. Keep names on one line and use an ellipsis only when available space is insufficient.
- Adjust chat header and composer constraints so long model names do not overlap neighboring controls or move the send button off-screen.
- Update administrator channel and timeout descriptions in English, French, Japanese, Simplified Chinese, and Traditional Chinese.

## Upgrade and Compatibility

- Startup migrates old fallback bindings into regular bindings with later priorities, retaining their health state.
- An existing positive global timeout is preserved. On the first migration, if the global timeout is absent or zero and legacy models have positive timeouts, the largest legacy timeout becomes the global value. Review Model policy after upgrading if the models previously used different timeout values.
- No new dependencies or required Redis service are introduced. Deploy the frontend and backend together using the application image.

After all four release images finish publishing, administrators can select beta.6 in **System update**. For a manual Compose upgrade, set `deploy/.env` to:

```dotenv
IMAGE_TAG=2.5.1-beta.6
UPDATER_IMAGE_TAG=2.5.1-beta.6
```

Remove or align any explicit `APP_IMAGE_TAG` or `SANDBOX_IMAGE_TAG` overrides, then deploy:

```bash
cd deploy
docker compose --env-file .env -f docker-compose.prod.yml pull
docker compose --env-file .env -f docker-compose.prod.yml up -d --no-build
```

The release tag triggers publication of `aivory-app`, `aivory-updater`, `aivory-sandbox`, and `aivory-sandbox-sidecar` under `ghcr.io/hjxwz123`, each tagged `2.5.1-beta.6` for `linux/amd64` and `linux/arm64`.

## Validation

- Backend tests for `internal/store`, `internal/api`, `internal/llm`, and `internal/tools` passed during implementation, including priority retries, global timeout selection, and compatibility migrations.
- TypeScript checking and focused browser checks passed during implementation. Browser checks covered the administrator model settings in all five languages and model picker behavior on desktop and mobile.
- No additional local tests or production builds were run during release preparation, as requested. GitHub Actions publishes the release images through the existing workflows.

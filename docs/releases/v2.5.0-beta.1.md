# Aivory v2.5.0-beta.1

> Test release / prerelease.

`v2.5.0-beta.1` introduces a unified, resizable artifact panel, browser-based document editing, and structured folder uploads for sandbox tasks. This release contains the work contributed in [PR #31](https://github.com/hjxwz123/Aivory/pull/31).

## Unified artifact panel

- Open streamed HTML artifacts, conversation attachments, sandbox outputs and knowledge-base documents in one right-side panel while keeping the conversation visible.
- Resize the desktop panel with a pointer or keyboard. The chosen width is persisted, clamped to the viewport and leaves usable space for the chat column.
- Use the same panel shell for document preview and editing, with a mobile side sheet and an error boundary that offers retry instead of leaving a blank surface.
- Render untrusted HTML through the shared sandboxed frame. Public previews on plain-HTTP deployments no longer upgrade same-origin assets to HTTPS incorrectly.

## Browser document editing

- Edit text, source code and HTML with CodeMirror. HTML edits update a live preview beside the editor.
- Edit DOCX documents in the browser and serialize the edited OOXML package for download or saving as a new copy.
- Edit XLSX cells in an accessible grid, preserve unmodified package content and calculate supported formulas.
- Edit text runs in existing PPTX slides and refresh the presentation preview from the patched file.
- Download the current edited result or save it as a new attachment copy. Editors are loaded only when needed to keep their larger dependencies out of the initial route.

Document editing is intentionally format-specific. PPTX editing changes existing text only; it does not add, move or redesign slide objects. XLSX editing is capped at 2,000 rows and 100 columns and does not implement the full Excel calculation engine. Complex Office documents may still differ visually from desktop Office applications.

## Folder upload and sandbox tasks

- Select an entire folder from the desktop composer toolbar or the mobile attachment menu.
- Preserve each accepted file's relative path in SQLite or PostgreSQL and stage it under `/workspace/uploads/<folder>/<path>`.
- Filter dependency and build directories, system files, disallowed extensions, extensionless files and selections over the count or total-size limits before upload. The composer reports what it skipped.
- Upload accepted files with controlled concurrency and show the folder as one expandable attachment node with aggregate size, progress and failure state.
- Generate `/workspace/aivory-uploads.txt` so the model can inspect the directory tree before using `python_execute` for project and directory tasks.
- Validate relative paths at the API boundary and retain sandbox-side path containment as a second defense against traversal.

Folder uploads intentionally bypass both document RAG ingestion paths; the model reads them directly from the sandbox. The conversation file drawer still lists folder members individually, empty directories cannot be represented by the browser picker, and a folder with 300 accepted files still performs 300 file requests with concurrency limited to three.

## Compatibility and deployment

- Add the `files.rel_path` database column through automatic SQLite and PostgreSQL migrations. Existing single-file attachments retain their previous behavior.
- Add lazy-loaded CodeMirror, DOCX, spreadsheet and OOXML dependencies.
- Synchronize `package-lock.json` with the new dependencies so the production Docker build can continue using `npm ci`.

## What to test

- Open HTML, PDF, DOCX, XLSX and PPTX files while chatting, then resize the panel by dragging and with the keyboard.
- Edit and immediately download or save a copy of each supported format, including after switching between view and edit modes.
- Upload source-code folders containing nested paths and duplicate basenames, confirm skipped-file reporting, and ask the model to inspect or run the project in the sandbox.
- Reload a conversation and confirm folder grouping and relative paths remain available.
- Verify light and dark themes, desktop and mobile layouts, and large or malformed Office documents.

## Upgrade

This is a prerelease intended for testing. Back up the database, uploaded files and generated artifacts before enabling it on a production deployment.

After the application and updater images finish publishing, administrators can select `v2.5.0-beta.1` from **System update**. For a manual Compose update, preserve the deployment's existing settings and use:

```dotenv
APP_IMAGE_TAG=2.5.0-beta.1
UPDATER_IMAGE_TAG=2.5.0-beta.1
```

```bash
docker compose -f docker-compose.prod.yml pull app updater
docker compose -f docker-compose.prod.yml up -d --no-deps --force-recreate updater app
```

Database migrations run automatically on startup. A rollback to an older application version leaves the additive `rel_path` column in place.

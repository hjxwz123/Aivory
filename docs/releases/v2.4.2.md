## What's Changed

Aivory 2.4.2 improves authentication policy, multi-device sessions, model availability enforcement, and administrator control over default tool behavior. It also gives Fast mode independent tool budgets, fixes web reading and direct image generation failure paths, and supports `markdown.new` as a Jina-compatible Reader fallback.

### Authentication and Account Access

- Separates password registration from OAuth/OIDC automatic provisioning. Administrators can now close direct email/password registration while still allowing first-time users to register through enabled third-party identity providers.
- Keeps the registration page usable in provider-only mode: OAuth buttons remain available while the password registration form is hidden, and the administrator settings page submits only settings that actually changed.
- Adds a `Remember password` option to the login page using the browser Credential Management API. Aivory does not add a server-side plaintext-password store; unsupported browsers retain their normal password-manager behavior.
- Allows the same account to remain signed in on multiple computers and phones. A new login appends a device session instead of revoking every existing refresh session.
- Preserves the existing refresh-token replay protection and validates account status, token generation, password/2FA security state, and OAuth provider state while a new session is committed, preventing a stale login from racing a security change.

### Model and Channel Availability

- Rejects disabled or non-chat models, models attached to disabled channels, and unsupported channels when saving the default, task, tool-routing, verification, or fallback model policy.
- Filters unavailable models out of administrator policy selectors and surfaces a localized configuration error instead of saving a model that cannot run.
- Enforces channel availability again when a conversation starts, so disabling a channel acts as an immediate runtime stop.
- Skips unavailable configured task and tool-routing models at execution time. Internal tasks fall back through the current conversation model and global default when usable; Auto tool routing falls back to the current conversation model.

### Default Tool Mode

- Adds an administrator-level default tool mode with `Auto`, `On`, and `Off` choices.
- Applies the deployment default only when a user has not selected an account-level default and the request does not explicitly select a mode. Existing explicit user and per-turn choices continue to take precedence.
- Returns the effective default in the authenticated profile so the composer and API resolve the same behavior.

### Fast Mode and Tool Reliability

- Gives Fast mode independent per-tool limits, a total system-tool call limit, and an elapsed-time budget instead of deriving it as a fixed fraction of normal mode.
- Keeps all provider-hosted tools available in Fast mode. Local system tools are hidden only when their Fast-mode limit is `0`; positive limits expose and cap them independently.
- Counts every attempted local system-tool call toward the total limit, including failed attempts, so alternating tools or repeating errors cannot bypass the per-turn ceiling.
- Extends web-reading execution time so the direct attempt can fail quickly while leaving time for the configured Reader fallback, and preserves partial batch results when only some pages can be read.
- Normalizes irrelevant `base_image_index` fields out of direct image-generation requests. A stale index no longer causes `action=generate must not set base_image_index`, and canonical duplicate detection no longer traps the corrected request behind the earlier invalid payload.

### Reader Compatibility

- Adds `AIVORY_TOOLS_WEB_FETCH_JINA_URL_MODE`. The default `escaped` mode preserves `r.jina.ai` behavior; `raw` appends the original target URL for compatible services such as `https://markdown.new`.
- Continues to fetch the origin directly first. The Reader service is used only after a direct timeout, network or HTTP failure, or an empty extracted result, while private and non-web targets remain blocked by the existing SSRF guard.

### Deployment Documentation

- Makes `ALLOWED_ORIGINS` prominent in the root environment examples, READMEs, and deployment guides. Domain and HTTPS reverse-proxy deployments must list each exact browser origin without a path, for example `ALLOWED_ORIGINS=https://chat.example.com`.
- Clarifies that same-origin IP/HTTP testing can leave `ALLOWED_ORIGINS` unset, while domain deployments without it may return `cross-site request blocked` on cookie-authenticated endpoints.

### Upgrade Notes

- No database migration or new mandatory environment variable is required.
- For domain or HTTPS deployments, verify `ALLOWED_ORIGINS` before upgrading. Multiple origins are comma-separated exact origins without paths.
- To use `markdown.new` after upgrading, set `AIVORY_TOOLS_WEB_FETCH_JINA_FALLBACK=true`, `AIVORY_TOOLS_WEB_FETCH_JINA_BASE=https://markdown.new`, and `AIVORY_TOOLS_WEB_FETCH_JINA_URL_MODE=raw`.
- Optional Fast-mode tuning variables are `AIVORY_LLM_FAST_TOOL_LIMITS_WEB_SEARCH`, `AIVORY_LLM_FAST_TOOL_LIMITS_WEB_FETCH`, `AIVORY_LLM_FAST_TOOL_LIMITS_FETCH_IMAGE`, `AIVORY_LLM_FAST_TOOL_LIMITS_IMAGE_GENERATE`, `AIVORY_LLM_FAST_TOOL_LIMITS_PYTHON_EXECUTE`, `AIVORY_LLM_MAX_TOOL_CALLS_PER_TURN_FAST`, and `AIVORY_LLM_MAX_TOOL_TIME_PER_TURN_FAST`. A local tool limit of `0` means hidden, not unlimited.
- Version-pinned Docker deployments should use `IMAGE_TAG=2.4.2` after the application, sandbox runner, and sandbox sidecar workflows finish publishing the matching multi-architecture images.

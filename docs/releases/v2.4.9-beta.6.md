# Aivory v2.4.9-beta.6

> Test release / prerelease.

`v2.4.9-beta.6` repairs Responses message IDs before channel fallback, including the final answer request after tool limits are reached. It also restores the dedicated workspace administration dialog.

## Responses compatibility and tool finalization

- When an upstream Responses endpoint rejects a message ID because it does not start with `msg_`, add the missing prefix to replayed message IDs and retry once on the same channel before recording a failure or selecting a fallback.
- Handle both HTTP validation errors and errors delivered inside an SSE stream. Preserve other request fields, including message phase, reasoning state and tool call associations.
- Treat the repaired rejection as a compatibility step: a successful repair does not add an Aivory failure usage row or duplicate token accounting. Upstream services may still record the rejected request themselves.
- Apply the repair to tool-free finalization requests too. After the existing 20-round tool limit, keep tools disabled and use the collected results to produce the final answer. An ID validation rejection can now be repaired without restarting tool execution.
- Keep retries bounded. Repeated ID rejection does not trigger channel fallback, and requests that already emitted output are not replayed. Other error handling retains its existing behavior.

## Workspace administration

- Restore the dedicated workspace management dialog for workspace administrators, including members, invites, policy, announcements, audit and statistics.
- Add **General** to that dialog for editing the workspace icon and description.
- Keep **Settings → Work** as a read-only workspace information page for both administrators and ordinary members, showing the leave action only when permitted.
- Administrators open the management dialog from the members menu; ordinary members open **Settings → Work** and cannot browse the member directory.

## Validation

- LLM module regression tests passed, including same-channel repair, fallback behavior and usage accounting.
- Added a complete 20-tool-round regression that verifies finalization retains all tool results, repairs the rejected message ID, returns the final answer and does not execute more tools.
- Workspace changes passed TypeScript, ESLint, 21 related tests and desktop/mobile interaction checks using simulated APIs.

## Upgrade and deployment

Select beta.6 in **System update** after the application and updater images finish publishing. This is a GitHub prerelease; the stable release remains unchanged.

For manual Compose updates, set:

```dotenv
APP_IMAGE_TAG=2.4.9-beta.6
UPDATER_IMAGE_TAG=2.4.9-beta.6
```

Use the deployment's existing Compose file and environment:

```bash
docker compose -f docker-compose.prod.yml pull app updater
docker compose -f docker-compose.prod.yml up -d --no-deps --force-recreate updater app
```

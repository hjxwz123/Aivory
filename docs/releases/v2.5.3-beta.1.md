# Aivory v2.5.3-beta.1

First test release of the 2.5.3 series, covering changes since **v2.5.2**. It improves context compaction and edit-and-resend recovery, and gives file deletion and request-signature failures more accurate HTTP status codes.

## Context Compaction

- Retry once on the same model when the first attempt exhausts its output budget and returns no visible summary. The retry can use spare room in the overall request budget while sending the same source and respecting the configured limit for the stored summary.
- Account for each provider attempt through the existing usage and billing flow. If the operation still yields no usable summary, retain the conversation history and existing summary. Stage logs now identify an empty summary as `empty_summary_output`.

## Editing and Resending Messages

- Include the original user message ID on edit-and-resend requests, including edits without attachments. Check that the original message and any explicit parent can be referenced before submitting a new branch.
- When the server rejects a stale message reference with `409`, discard the rejected local branch and reload the conversation. The user can reopen the message and edit again. The server continues to enforce the original branch and conversation boundaries.
- Reuse an in-progress conversation refresh after stopping a reply, so an edit started at the same time does not race a second refresh.

## Conversation Deletion and Request Signatures

- Return `404` when a conversation file is missing or the caller cannot delete it. Unexpected storage errors remain `500`. Deleting an entire conversation now also distinguishes a missing conversation from an unexpected server error.
- Return `503` when the server cannot record a request's one-time signature nonce. Repeated signatures still receive `403`, and the request is rejected in either case.

## Upgrade Notes

- Deploy the frontend and API together to test the edit-and-resend recovery. No database migration is required.
- Each compaction attempt that consumes model tokens is billed. The extra attempt only applies to an empty result that reached its output limit and has sufficient room in the overall request budget.
- This is a GitHub prerelease. **v2.5.2** remains the latest stable release. Once matching installers are available, deployment administrators can select this version in **Admin > System > Desktop Client** to offer it to their users.

## Validation

- 55 frontend conversation-store tests, including a stale edit branch returning `409` and recovering the server's current message path.
- TypeScript checking and focused Go tests for compaction, parent-message validation, conversation and file deletion, and signature verification. The compaction regression covers saving the summary returned by the second attempt.
- Production frontend build, package and lockfile version consistency, and Git whitespace checks.

# Aivory v2.5.1-beta.8

> Test release / prerelease with opt-in Generative UI, direct administrator Skill commands, and a locally bundled desktop frontend.

## Generative UI

- Select **generative-ui** from the composer `/` menu to request visual answers. The enabled administrator Skill is installed on server startup and does not need to be copied into a personal library. It is not automatically bound to every model.
- Render versioned `aivory-ui` JSON as themed metrics, line/bar charts, tables, steps, keyboard-accessible tabs, and accordions directly in assistant messages.
- Render self-contained `aivory-html` as an interactive interface inside the answer, including throttled live updates while streaming. Ordinary HTML code keeps the existing preview behavior.
- Use compact controls, minimal lines, readable charts at narrow widths, contained table scrolling, theme-aware colors, and five-language interface labels.
- Validate preset sizes, dimensions, finite numbers, supported component types, and nesting. Malformed completed output remains available as readable source.
- Isolate generated HTML with two opaque sandboxed frames and restrictive CSP. Network requests, remote assets, navigation, cookies/storage, parent access, and the desktop native bridge are unavailable. Only bounded child-window height updates are accepted.
- Support assistant visualizations in normal, private, and shared conversations. User messages, reasoning, and tool output do not execute this protocol.

See [Generative UI documentation](https://github.com/hjxwz123/Aivory/blob/v2.5.1-beta.8/docs/generative-ui.md) for trigger examples, exact protocols, permission rules, and runtime limits.

## Skill Commands and Model Bindings

- Include permitted enabled administrator Skills in the `/` menu even when users have not added them to their library. Keep catalog instructions and internal trigger descriptions out of metadata responses.
- Resolve direct catalog selections on the server, preserve them for regeneration, and revalidate group and workspace permissions and enablement.
- Apply the same Skill only once when it is both model-bound and explicitly selected. Explicit selection takes precedence for the current turn; an edited personal copy also takes precedence over a submitted direct catalog reference.
- Avoid duplicate instruction loading through `use_skill`, including timeout fallback models and the code-defined document-generation Skill.
- Make administrator Skill assets available to permitted explicit selections. Retain a personal-library fallback when a new frontend encounters an older server without the command endpoint.

## Locally Bundled Desktop Frontend

- Package the frontend inside the desktop application. UI, fonts, scripts, and styles run locally at a virtual HTTPS origin; only API calls are forwarded to the configured server. No local HTTP service is started.
- Keep native credentials in per-server persistent partitions and stream API responses without buffering the whole answer. Preserve cancellation, file transfers, voice sockets, payment windows, and public server links.
- Keep the server address through app updates. Official installers start with no preset address and ask for the deployment URL on first launch.
- Preserve the current page and drafts while offline, then restore authentication when connectivity returns. Browser authorization completes in place and respects the intended safe route.
- Show third-party authentication and passkey registration in the system browser where appropriate. Native login remains browser authorization or account/password; account settings can manage existing passkeys and open the real server origin to register a new one.
- Record the initiating desktop device in browser authorization and make authorization expire in place. Await cancellation of pending browser authorization before applying password login.
- Integrate macOS window chrome with the app, sign modified bundles correctly, verify signatures, and include required ad-hoc entitlements. These test Mac builds are not Developer ID notarized; trusted distribution still requires Apple credentials.

## Notifications, Promotional Messages, and Sidebar

- Rename the existing popup announcement to a popup message and allow administrators to customize its action text and URL.
- Add administrator-managed notifications with create/edit/delete, historical entries, per-user read/dismiss state, and an accessible user notification viewer. New notifications can appear on site entry, with a dismiss option.
- Include notification state in backup and audit support. Remove the obsolete Help entry from the user avatar menu.
- Allow collapsing both the entire Projects section and each project's conversations. Persist the chosen sidebar state.
- Fix the desktop download hook's non-browser rendering, model-channel status text sizing, and static-check errors in administrator desktop and channel-header controls.

## Installers and Container Images

GitHub Actions builds this release tag on native runners and attaches verified installers after all platform jobs succeed:

| Operating system | Architecture | Packages |
| --- | --- | --- |
| Windows | x64 | `Aivory-2.5.1-beta.8-win-x64.exe` |
| Linux | x64 | `Aivory-2.5.1-beta.8-linux-x64.AppImage`, `Aivory-2.5.1-beta.8-linux-x64.deb` |
| macOS | Apple Silicon / arm64 | `Aivory-2.5.1-beta.8-mac-arm64.dmg`, `Aivory-2.5.1-beta.8-mac-arm64.zip` |
| macOS | Intel / x64 | `Aivory-2.5.1-beta.8-mac-x64.dmg`, `Aivory-2.5.1-beta.8-mac-x64.zip` |

`SHA256SUMS.txt` is published alongside the seven installers. The desktop workflow checks installer names, bundled frontend/runtime files, release versions, and Mac signatures before upload. Builders can still configure `AIVORY_DESKTOP_BASE_URL` for their own deployment.

The release tag also builds multi-architecture application and updater images:

```text
ghcr.io/hjxwz123/aivory-app:2.5.1-beta.8
ghcr.io/hjxwz123/aivory-updater:2.5.1-beta.8
```

If a registry mirror has not synchronized a new tag yet, use the corresponding `ghcr.io` address directly.

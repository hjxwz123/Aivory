## What's Changed

Aivory 2.2.10 is a focused performance release for long and actively streaming chat responses. It reduces repeated Markdown rendering work as a response grows, keeping completed sections stable while updating the changing tail. The rendered content, supported Markdown features, citation behavior, and stored conversation data remain unchanged.

### Long Response Rendering

- Split rendered Markdown into independently memoized block views for headings, paragraphs, lists, code, Mermaid diagrams, blockquotes, formulas, separators, and tables.
- Prevented completed leading blocks from repeatedly running inline or block Markdown conversion, sanitization, and related rendering work whenever new text arrives at the end of a streaming response.
- Limited most streaming updates to the trailing block whose content is still changing, reducing avoidable React rendering and main-thread work on long answers.
- Continued tokenizing the complete Markdown source before rendering so block boundaries, incomplete trailing syntax, and final output semantics remain consistent with previous releases.
- Preserved document citations, line-break preferences, code-preview identities, Mermaid handling, KaTeX output, table layout, and block-level entrance animations.
- Kept the final non-streaming render authoritative: when generation completes, blocks reconcile once with the completed content and normal non-live presentation.

### User Experience

- Improved responsiveness while receiving long explanations, reports, research output, code-heavy answers, and other responses containing many Markdown blocks.
- Reduced redundant work for already completed sections without virtualizing, hiding, truncating, or delaying visible response content.
- Preserved scrolling, citation clicks, code controls, diagrams, formulas, and responsive table behavior.

### Compatibility and Upgrade Notes

- No database migration, manual SQL, data conversion, or knowledge-base reindexing is required.
- No server API, provider request, model configuration, tool execution, billing, permission, or context-compaction behavior changes are included in this patch.
- Existing conversations and generated responses require no migration and render through the optimized path after the frontend is updated.
- For Docker deployments, set `IMAGE_TAG=2.2.10` and leave `SANDBOX_IMAGE_TAG` unset after the matching application and sandbox image workflows complete.

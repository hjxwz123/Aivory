## What's Changed

Aivory 2.4.3 focuses on everyday reliability and a clearer path from administration to chat. It adds a more efficient channel and model workflow, makes tool-mode choices conversation-scoped, prevents concurrent sends from corrupting a branch, and introduces queued follow-up messages. It also adds a read-only browser for conversation sandbox files, disables image generation when no image model is available, and refreshes several chat and landing-page details.

### Channels and Model Configuration

- Adds a compact channel model workflow: type a model identifier to add it one at a time, or fetch the upstream models endpoint and select the models to import in bulk.
- Reports duplicates, unsupported entries, empty upstream responses, partial imports, and request failures without silently pretending that a model was added.
- Accepts custom OpenAI-compatible API roots such as `/v1`, `/v2`, and `/v3`; the channel editor no longer rejects a valid HTTP(S) base URL merely because it does not end in `/v1`.
- Keeps model capabilities, channel state, and policy selectors aligned so a disabled or unavailable model cannot be selected for a new policy or conversation.

### Tool Modes and Internal Model Calls

- Moves the user's tool-mode choice from a global account preference to the conversation. The administrator controls the deployment default; a user can override it only inside a specific conversation, and a new conversation starts from the administrator default again.
- Preserves existing user data through an automatic migration while removing the obsolete global setting from the active API and personalization page.
- Applies a configured model's `extra_params` to internal title, task, tool-routing, compaction, verification, and moderation calls as well as normal chat requests.
- Keeps internal-task output bounded and more useful by increasing title generation capacity and allowing tool-route decisions enough output to return a valid decision.

### Conversation Reliability and Queued Sends

- Adds per-user, per-branch generation leases so concurrent normal sends on the same linear branch are serialized on the server.
- Recovers rejected or interrupted sends on the client instead of leaving an optimistic user message spinning forever; stopping a response now reconciles the branch before another message can start.
- While an assistant response is active, the composer can place one follow-up message into a per-conversation queue. The queued text, attachments, model, modes, parameters, skills, and tool selections are captured at enqueue time.
- The queue displays a compact pending row above the composer, supports withdrawing the message back into the draft, and automatically dispatches it after the current response finishes, stops, or fails, including when another conversation is open.

### Sandbox File Browser

- Adds a read-only sandbox drawer beside the conversation files drawer. Users can inspect the current conversation's sandbox files, enter folders, navigate breadcrumbs, refresh the listing, and preview supported files.
- Sandbox contents cannot be deleted or changed from the chat UI. The API verifies conversation ownership, confines paths to safe relative names, and prevents active sandbox content from executing in the browser during preview.
- Adds standalone sandbox guide and API links to the sandbox service documentation.

### Image Generation Availability

- Hides the local image-generation tool from normal model tool declarations when no enabled image model exists.
- Shows the tool in the administrator catalog as unavailable with a configuration hint, while retaining it in the admin list for visibility.
- Rechecks image-model availability immediately before execution so stale tool selections fail with a clear configuration error instead of a provider request that cannot succeed.

### Chat and Landing UI

- Shows a small animated indicator beside a conversation title while that conversation is actively receiving an assistant response.
- Removes redundant separators from empty project and workspace menus.
- Refines the landing-page use-case cards with neutral icon surfaces, restrained borders, and tighter information hierarchy.

### Backup and Migration Reliability

- Makes administrator backup imports validate and restore data atomically across the database, files, vector data, and sandbox-related state, with integrity checks and clearer failure handling.
- Adds generation-lease schema migration automatically at startup; no manual SQL is required.

### Upgrade Notes

- No new mandatory environment variable is required.
- Database migrations run automatically. Back up the instance before upgrading and allow one application instance to complete migration before scaling out.
- Version-pinned Docker deployments should set `IMAGE_TAG=2.4.3` after the application, sandbox runner, and sandbox sidecar workflows finish publishing the matching `linux/amd64` and `linux/arm64` images.
- The sandbox browser is read-only. Existing sandbox sessions remain available to tools; a session that has expired is shown as unavailable rather than recreated by browsing.

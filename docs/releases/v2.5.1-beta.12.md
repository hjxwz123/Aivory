# Aivory v2.5.1-beta.12

Test release adding administrator tool-call diagnostics and fixing oversized document embedding inputs, PostgreSQL channel updates, and OpenRouter Decisions compatibility.

## Tool and MCP Call Logs

- Add **Tool call logs** under **Audit & logs** at `/admin/logs/tools` for built-in tools and platform/user MCP calls executed by Aivory.
- Keep the table focused on summaries. Open a row to load full diagnostics in a right-side drawer, including log/call IDs, user, model, conversation, message and workspace references, arguments, results, duration, and specific errors.
- Capture outbound HTTP method, URL, status, timing, and bounded request/response excerpts. Search diagnostics include search terms, SearXNG engine errors, and partial search or page-fetch failures.
- Add an independent **Record only failed tool calls** option at `/admin/settings/logging`. It defaults to enabled; disable it to record successful calls as well.
- Honor the existing request-body logging setting, redact credentials, and omit binary bodies. Store logs through a bounded asynchronous queue to keep database writes off the tool-return path.
- Support filtering, individual deletion, and deletion of filtered records. Include tool logs in database backups and user-data cleanup.
- Add translations in English, Simplified Chinese, Traditional Chinese, Japanese, and French.

## Document Embedding

- Split oversized protected OCR paragraphs, tables, and code blocks before embedding. These blocks could previously bypass ordinary chunk sizing and fail with `embedding input ... exceeding text-embedding-v4 limit 8192`.
- Prefer line and sentence boundaries; split oversized individual lines at UTF-8 character boundaries while retaining their text.
- Bound final inputs including heading prefixes and overlap, with a conservative byte ceiling and headroom below known model limits.
- Preserve the order and one-to-one correspondence of stored child chunks and embedding vectors. Ordinary chunks keep their existing representation.
- Keep the existing embedding input validation and provider configuration. Failed uploads can be retried after upgrading.

## PostgreSQL Channel Updates

- Fix `ON CONFLICT DO UPDATE requires inference specification or constraint name (SQLSTATE 42601)` when saving supported channel models.
- Use the existing unique index expression, `(channel_id, lower(trim(request_id)))`, as the explicit conflict target in both upsert paths.
- Preserve case-insensitive request-ID matching on PostgreSQL and SQLite.

## OpenRouter Decisions

- Accept complete `/decisions` and `/systemone` URLs without appending a second resource suffix.
- Support `https://openrouter.ai/api/alpha/decisions` directly. OpenRouter API roots also resolve to its TypeSafe-compatible System One endpoint.
- Handle the `typesafe/` model namespace and dated releases returned for aliases such as `typesafe/jev-1.13`, while retaining concrete-version checks.
- Retain typed answer validation, token accounting, request diagnostics, administrator pricing, and request deadlines.

Example configuration:

```text
Model protocol: TypeSafe Decisions (typesafe.decisions)
Channel Base URL: https://openrouter.ai/api/alpha/decisions
Channel API key: your OpenRouter API key
Model request ID: typesafe/jev-1.13
```

Model availability depends on OpenRouter's catalog and account access. See [TypeSafe Decisions configuration](https://github.com/hjxwz123/Aivory/blob/v2.5.1-beta.12/docs/typesafe-decisions.md).

## Upgrade and Validation

The application creates the tool-log table and indexes automatically on startup for PostgreSQL and SQLite. Existing data and settings are preserved; the new tool-log option defaults to recording failures only.

Backend compilation, frontend typechecking, targeted linting, and static checks passed during implementation. No automated test suites were run, as requested. GitHub Actions builds the tagged source and checks the packaged artifacts.

## Desktop Installers and Container Images

This release includes the web frontend and the locally bundled desktop frontend. GitHub Actions builds the following installers and attaches `SHA256SUMS.txt` after all desktop builds succeed:

| Operating system | Architecture | Packages |
| --- | --- | --- |
| Windows | x64 | `Aivory-2.5.1-beta.12-win-x64.exe` |
| Linux | x64 | `Aivory-2.5.1-beta.12-linux-x64.AppImage`, `Aivory-2.5.1-beta.12-linux-x64.deb` |
